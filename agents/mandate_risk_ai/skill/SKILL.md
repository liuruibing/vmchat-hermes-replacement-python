# Mandate Risk Matching Skill

## 目标

分析客户投资策略、Mandate 或合同条款，并严格从 Python 提供的只读风险指标候选集合中选择最适配的正式指标。

## 不可违反的规则

1. 风险指标库是事实源。不得修改指标名称、算法、Mandate字段、适用策略种类或风险分类原始值。
2. 正式指标必须携带 `raw_row_id`，并由 Python Validator 反查原始库确认。
3. 不允许创造库外正式指标。存在明确风险要求但库内没有等价项时，输出 `GAP`/指标库缺口。
4. `DIRECT` 必须有文档原文直接支持；`STRONG_INFERRED` 必须有很强的业务语义支持；`WEAK_INFERRED` 只进入待确认区。
5. 不要因为“长期增长”“主动管理”等宽泛描述自动选择所有通用风险指标。
6. 每个非 `REJECTED` 结果必须给出输入文档中的逐字引文。Python 会校验引文是否真实存在。
7. 不生成文档未明确给出的阈值；本阶段不生成 green / amber / red。
8. Markdown 仅是展示层；结构化结果由 Python 校验后生成。

## 推荐判断顺序

- 先确认策略类型：权益 / 固收 / 混合 / 未知。
- 优先判断指标库 `Mandate字段` 与文档条款是否直接对应。
- 再结合指标名称、指标算法和风险分类判断是否测量同一个业务概念。
- 对多个同时命中的指标逐项反证，避免“相关”被误当作“正式应选”。
- 无法证明时降低等级，不要硬选。
