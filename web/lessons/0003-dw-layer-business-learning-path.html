单元 3：DW 层业务知识与指标 4 步入手指南

在面对庞大的金融 DW 表（如 MPRF_F_PLAN_DAYNETVALUE）和复杂的指标公式时，容易陷入“看代码看不懂业务，看业务对不上字段”的困境。高效的学习路径是遵循以下 4 步入手模型。

来源：职年计划查询SQL_字段计算逻辑分析.md 来源：字段清洗调用梳理.md

第 1 步：抓核心实体与基础基准指标 (Foundation Metrics)

不要一上来就看夏普比率或总体加权，先搞懂 DW 表中最基础的 3 个底层事实字段：

  • F_NETVALUE：资产净值（当日组合资产总规模，来自于估值表 701A）。
  • F_CAPITAL_IN / F_CAPITAL_OUT：投资分配流入与提取流出。
标准现金流日收益率公式 (r_t):
r_t = (F_NETVALUE_t - F_NETVALUE_{t-1} - F_CAPITAL_IN_t + F_CAPITAL_OUT_t) / F_NETVALUE_{t-1}

第 2 步：区分收益率的两种聚合方式 (Time vs Portfolio)

搞清楚“单个计划随时间的复利”与“多个计划跨组合的加权”在算法上的根本区别：

  • 时间维度复利 (单计划连乘)：单个计划在 N 天内的累计收益率等于每日日收益率的几何连乘：R = ∏(1 + r_t) - 1。
  • 组合维度加权 (总体加权函数)：多个计划汇总时，不能直接相加连乘结果。必须先用前一自然日规模 701A 计算每日总体加权收益率 r̄_t，再进行几何连乘：R_total = ∏(1 + r̄_t) - 1（调用 GET_OVERALL_WEIGHTED_RETURN_R/W）。

第 3 步：识别特例口径与业务避坑 (Business Caveats)

重点识别代码中的业务命名惯例与监管特殊规则：

【TCZ 真实含义】: TCZ 沿用历史命名“剔除支付”，源码实际逻辑为 VC_NAME_GLR LIKE '太平养老保险%'（剔除太平养老管理组合）。

【14号文回撤口径 F_MAXDRAW_DAY】: 非常规净值曲线峰谷 drop，而是“日收益率前高后低差”公式：Max ( (r_g - r_k) / (r_g + 1) )，其中 g < k。

第 4 步：从逐日加权序列推导风险指标 (Risk Derivation)

搞清风险指标（波动率 F_VIX、夏普 F_SHARP）在 SQL 合计行的推导逻辑：

SQL 合计行不会对单个计划的波动率直接取平均，而是先生成每日总体加权日收益率序列 r̄_t，再计算该收益率序列的标准差并年化（乘以 √250），得到符合监管合规要求的组合总体风险指标。
