# Mission: 以“职年计划综合查询页面”为核心贯通 SQL 与 DW 业务逻辑

## Why
以具体的“职年计划综合查询报表页面”为切入点，从前端展示列与筛选条件出发，垂直打通背后的复杂 UNION ALL SQL 逻辑、DW 层存储过程清洗以及物理表血缘，能够独立看懂任何报表页面的底层逻辑并具备 SQL 修改与指标排查能力。

## Success looks like
- 能将前端界面的每一个筛选条件（如时间范围、计划类型 VC_PLAN_TYPE）与 SQL WHERE 过滤子句精确对应
- 能将前端表格的每一列指标（RK, PLANCODE, RYIELDG, STBC, F_VIX 等）映射到 SQL 输出字段与 DW 物理表字段
- 能够清晰解释前端页面中“单计划明细行”与“合计行”在页面渲染和 SQL 计算上的区别与联系
- 能够基于具体页面需求定位数据异常点或编写/修改对应的查询 SQL

## Constraints
- 围绕“职年计划综合查询 SQL”对应的真实页面场景展开
- 通过交互式 Lesson、页面-SQL 对照卡与 E2E 测试保持实践反馈

## Out of scope
- 无关的第三方 UI 控件实现细节
