# DBX 数据库知识库增量维护流程 (Incremental Maintenance Workflow)

本文档固化当收到新的数据库文档、新增 SQL 源码导出、元数据变更或数据探查输入时，知识库的增量更新规则与操作规程。

---

## 1. 六步增量更新标准规程

当向知识库注入新的分析资料或 DBX 探查结果时，必须按以下步骤处理：

```text
[ 1. 读取目标领域现有卡片与证据索引 ]
                 │
                 ▼
[ 2. 在 09-Evidence/ 下建立新证据条目 (E1/E2/E3/E4) ]
                 │
                 ▼
[ 3. 比较新旧证据结论 ]
       ├── 结论一致 ──► 在现有卡片 Front Matter 追加 sources 引用条目
       └── 结论矛盾 ──► 写入 99-Inbox/Conflicts.md 并将卡片标为 conflicted
                 │
                 ▼
[ 4. 仅更新有新证据支持的 status, confidence 与 last_verified ]
                 │
                 ▼
[ 5. 重新生成受影响的学习卡与路线图 ]
                 │
                 ▼
[ 6. 运行 npm run test:database-knowledge 校验门禁 ]
```

---

## 2. 维护红线与禁忌

1. **严禁删除历史证据**：禁止任何删除、覆盖原有 `09-Evidence/` 文件或 `sources` 历史记录的操作。
2. **严禁静默消除冲突**：发现新证据与种子文档或历史代码矛盾时，**必须**保留原结论并将冲突登记至 [`99-Inbox/Conflicts.md`](../99-Inbox/Conflicts.md)。
3. **严禁无证据升级状态**：无新的 E1/E2 支持时，不得将 `supported` 或 `inferred` 升级为 `confirmed`。
4. **校验脚本门禁**：更新后必须运行 `npm run test:database-knowledge`，确保零格式错误与内部链接断链。
