本文档定义 `database-knowledge/` 目录下所有 Markdown 知识卡片与证据产物的标准结构、Front Matter 字段规范、证据等级分类及知识状态判定规则。

## 2. 证据等级分类体系

知识库遵循严密的证据分类体系，禁止脱离证据升级结论状态：

| 等级标识 | 名称 | 定义与定义域 | 来源示例 |
|---|---|---|---|
| **E1** | 人工与业务文档证据 | 权威业务规划、指导手册、需求分析文档 | `outputs/taiping_pension_learning_roadmap.md` |
| **E2** | SQL 与存储过程源码证据 | 已验证的存储过程、函数导出、查询 SQL 源码 | `DW_ZNST_INDEX_NEW` 包源码、前端查询 SQL |
| **E3** | 数据库元数据证据 | DBX `dbx_describe_table` 返回的 PK/FK/约束/注释 | `DD_DW.MDIM_FUND_INFO` 结构 |
| **E4** | 数据探查与分布证据 | `dbx_execute_query` 执行 `ROWNUM <= 20` 的只读探查 | `DISTINCT VC_TYPE_IN` 统计分布 |
| **I** | 推断与启发式猜想 | 仅由命名习惯、相似字段名或 AI 分析得出的假设 | 由 `VC_PLAN_CODE` 猜测与 `VC_PLAN_LIC_ID` 外键关系 |

## 3. 知识状态判定与变迁规则

卡片的 `status` 字段根据所持有的顶级证据等级判定：

1. **`confirmed` (已确认)**：
   - 必须拥有至少一条 **E1**（权威业务文档）或 **E2**（存储过程/SQL 源码）证据支持。
   - 证明该结论在业务逻辑或计算代码层面有明确定义。

2. **`supported` (已支持)**：
   - 仅拥有 **E3**（数据库元数据）或 **E4**（数据分布/样例）证据支持。
   - 表明该对象在数据库中实际存在并容纳数据，但尚缺乏明确的业务算法代码/文档佐证。

3. **`inferred` (推断中)**：
   - 仅基于命名相似性、结构推理或启发式猜测（标记 **I**）。
   - 不能作为既定数仓事实使用，需在卡片中显式标出待确认点。

4. **`conflicted` (冲突)**：
   - 存在两条或以上相互矛盾的证据（例如建表注释 vs 存储过程实际过滤条件）。
   - **禁止**删除或改写种子结论来“解决”冲突。必须同时保留双方观点、各自来源路径及冲突分析。

5. **`open` (待确认/开放问题)**：
   - 尚未取得任何证据或缺乏关闭条件的候选概念/字段/规则。

## 4. 样例数据与脱敏安全门禁

1. 样例查询必须显式附加 `ROWNUM <= 20` 或 `LIMIT 20` 限制。
2. 样例数据**严格禁止**包含真实客户姓名、身份证号、银行账号、手机号等敏感信息。
3. 证据文件中仅保存脱敏、最少必要的字段值。
4. 所有数据查询必须为**单条只读** SELECT 语句，禁止任何 DELETE、UPDATE、INSERT、DROP、ALTER、TRUNCATE 等写操作。
