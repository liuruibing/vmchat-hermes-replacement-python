# Mandate 风险识别：后续实施与验收计划

更新：2026-09-29。先读 [当前进度](mandate-risk-current-status.md)，并重新检查分支、工作区差异和原始 PDF；其他人的未提交改动不得覆盖。优先解决正确性，再联调静态页。所有新代码避免以 PDF 文件名、样例条款编号、固定指标行号或预期主表数量作为分支条件。

## 1. P0：合同量化条款去向门禁

真实失败：权益 PDF 第 6 页 §9.10 两档 TPMF 市值限额已被 Python 切成独立原文条款，模型整条未输出，系统却 `run.completed`。现有候选行门禁只防止“已召回的指标漏判”，不防合同要求漏读。

建议从 `split_document_clauses` 的真实条款、页码、source span 构造待复核量化线索（限额/目标的数值、单位、币种、条件、对象），不要把所有带数字的句子自动认定为指标库缺口。复用当前语义判断调用返回逐线索去向：已接受的匹配、待确认、已接受的缺口、可说明的排除或未决。Python 必须校验线索 ID 与原文、引用的库行/缺口确实在 `validate_model_result` 后存活；一条款多档、多数值不能只报一档；虚构条款、被校验器丢掉的 gap、把明确限额伪称背景都不能算覆盖。遗漏或未决须明确 `run.failed`/人工复核，不输出看似完整的正式报告。跨页两段分别引用，不能合成一条假引文。

先用与原样本不同的两档币种/比例合同写工作流红测，确认旧代码漏报仍完成；再加“只报一档”、错条件、假条款 ID、gap 被丢弃、定义/许可/页码数字合理排除、零线索的正反例。完成后跑受影响定向测试及两份原 PDF 的接口复测。真实模型失败率、时延与 token 用量也需记录；当前两次真实调用各约 40k tokens，不应无说明地再加一次全 PDF 调用。阶段 3 的实施代理在本次交接前被停止，暂无半成品代码需要继续沿用。

## 2. P1：DIRECT 与算法口径等价

用户已决定：合同的“年化事前 Tracking Error ≤100%”与库里只写 `TE=σ(Rp−Rb)` 不明同口径，先放待确认。补一个**不按指标名称写死**的算法限定词门禁：合同若要求事前预测、年化、购买时点、特定分子/分母或持仓层级，而库算法未说明，应降级或未决，不能仅凭英文概念词命中进主表。用不同名字的合成指标写正反例，再验证权益跟踪误差确实移出主表。

同时复核权益“单一证券占比”的库算法分母与合同“子组合市值”口径，及固收久期、剩余期限、评级等只是定义/策略/许可还是正式监控要求。固收主表 0 项不应为贴近 Excel 而强行增加；新购资产 +10 bps 的对象不是组合超额收益率。测量对象明显不同的弱推断（例如组合自身流动性指标对 TPMF 底层流动性）应拒绝或标明未决，不因主题相近保留在待确认。

## 3. P1：PDF 原文与跨页溯源

当前仅去除了权益第 7 页续句前的印刷页码；第 6 页 `single` 与第 7 页 `sector<100%` 仍分属两个 source span。设计显式跨页关联或未决提示，保留各页原文、偏移和页码，不把页眉/页脚拼进合同句子。用不同页码和不同跨页限额测试；页码清理的通用规则也要防止误删真正的章节编号。修改解析后重算 `clause_id`，不能沿用旧编号做验收。

## 4. P2：两份 PDF 证据矩阵与真实接口验收

每轮从同一 `PdfDocumentParser` 生成条款清单，逐项记录合同原文、页码、数值/单位/条件、测量对象、库算法及最终去向。固收至少核对购买时点 +10 bps；权益至少核对超额收益、跟踪误差、单券/行业限额、TPMF 低于/达到 RMB 1 billion 两档、分散度、1 日/7 日流动性和 MMF 限额。定义、资产许可和临时例外数字作负例。不要用固定主表数量当断言。用本分支新进程直接走上传、run、SSE，至少重复两轮真实模型观察波动；保留 run ID、模型、代码版本、终态、用量和失败原因。确定性伪 Provider 测试是回归门禁，真实模型观察不是稳定准确率证明。

## 5. P3：静态页最后联调与交付

后端证据矩阵可审计后，再处理前端仓库的 `static/test-mandate-risk.html` 作为正式入口：连接可确认版本的后端，测试上传、SSE 报告、基于当前报告问答、无依据拒答和 `run.failed`/待人工复核状态。前端仓库目前的默认临时 Cloudflare 隧道及代理配置可能过期，不能把本地 8000 的旧进程或页面 HTTP 200 当作闭环成功。Vue `ddrisk-ui`/业务页不作为当前后端验收前置条件。前端改动需在前端仓库独立核对、测试和提交。

## 每阶段交付门禁

开始时 `git status --short --branch`，只改受影响文件；先用红测复现，再实现、绿测并 `git diff --check`；最后列出未解决项。保持原始指标 CSV 不变；对可更新的指标库不依赖固定 34 行。新指标的原始名称、算法、策略和版本来自库本身，别名、分组与现有按名字写的例外应逐步改成数据驱动或明确标为兼容规则。没有通过合同覆盖和算法等价验证前，不要宣称“新 PDF / 新指标已通用支持”。
