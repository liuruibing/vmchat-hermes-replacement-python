# 36 个 VM 模块业务含义全景与指标合并边界规范

> 本文档系统梳理了银河证券/FOF投研项目中 **全部 36 个 VM 报表模块的业务含义**，并从量化投研数据模型、数仓物理主键以及组合管理业务视角，深度剖析了 **“哪些指标可以合并展示、哪些绝对不能合并展示”** 的底层逻辑，同时对既有 Wiki 文档中关于合并描述的缺陷进行了全面修正。

---

## 一、36 个 VM 模块业务含义全景分类

按照量化投研与组合分析的标准框架，36 个业务模块划分为 8 大业务板块：

### 1. 资产配置与大类仓位板块
1. **`assetContribute`（大类资产收益贡献）**：按股票、债券、期货、基金、理财、现金等维度，统计各资产在统计区间内的期末市值、占资产净值比（%）、区间收益额（元）、费后收益额、收益贡献比例及净值贡献度。
2. **`fixedPositionTiming`（固定收益类持仓时序）**：追踪组合中债券类资产（国债、金融债、企业债、中票、转债等）合计市值及占净比的每日/周走势。
3. **`cashPositionTiming`（现金类持仓时序）**：统计银行存款、清算备付金、结算保证金及货币基金等现金管理工具的市值与占净比时序。
4. **`holdPlate`（A股持仓指数及板块时序）**：统计主板、创业板、科创板等上市板块的持仓市值变化，观察资产在不同市场板块的配置迁徙。

### 2. 股票与权益投资板块
5. **`stockExposureTiming`（股票净敞口时序）**：跟踪股票多头市值占比、股指期货空头套保比例及二者轧差后的实际合成净敞口，反映股票多空策略的仓位暴露。
6. **`averagePePb`（持仓平均PE/PB时序）**：组合持仓个股的整体加权平均市盈率（PE）、市净率（PB）、市销率（PS）及 PCF 历史走势，评估持仓估值水位。
7. **`hldStockNumTime`（持股数量时序变化图）**：每个估值日组合实际持有的不同股票只数，衡量选股集中度与分散化程度。
8. **`topTenOrTopFiveStockPositionTime`（前十大/前五大股票持仓时序）**：跟踪前五大与前十大重仓股票合计市值占资产净比的时序变化。

### 3. 行业分析与行业配置板块
9. **`swInduStockAlloca`（申万行业配置）**：以申万一级行业（31个门类）为基准，对比持仓行业权重与业绩基准成分行业权重，分析超配/低配幅度。
10. **`swInduStockAnal`（申万行业分析）**：基于经典 Brinson 模型，在申万行业体系下分解组合的行业配置超额收益（Q1-Q0）、个股选择超额收益（Q2-Q0）与交互效应。
11. **`swInduStockVala`（申万行业估值）**：统计组合重仓的申万行业当前整体估值水位、PE-TTM、PB 及其在近三年历史分位数位置。
12. **`hsInduStockAlloca`（华泰柏瑞行业配置）**：在华泰柏瑞行业分类体系下的行业权重与配置风险暴露。
13. **`hsInduStockAnal`（华泰柏瑞行业分析）**：在华泰柏瑞行业分类口径下进行 Brinson 归因收益拆解。
14. **`hsInduStockVala`（华泰柏瑞行业估值）**：华泰柏瑞体系下的行业估值水位与相对偏离。
15. **`positionIndustry`（行业持仓分布）**：报告期末股票资产在各行业的截面市值分布与占比。
16. **`industryMonitor`（行业监控）**：包含行业配置时序面积图与截面饼图的多维行业偏离监控。
17. **`topFiveIndustryTime`（前五大行业时序）**：动态追踪组合在历史时间序列上前五大重仓行业的集中度变化。
18. **`tenProfitIndustry`（前十大盈利行业）**：统计周期内贡献正向收益金额排名前十的行业榜单。
19. **`tenLossIndustry`（前十大亏损行业）**：统计周期内造成负向亏损拖累金额最大的前十行业榜单。

### 4. 固收与债券投资板块
20. **`bondConcentrate`（债券持仓集中度）**：统计债券组合前五大、前十大持仓债券市值占比与久期/信用区间分布。
21. **`bondDurationTiming`（债券久期变动时序）**：追踪组合中债券资产整体修正久期（Modified Duration）走势。
22. **`fundDurationTiming`（组合加权久期时序）**：以个券市值占基金总资产比重为权重计算的组合加权久期时序曲线。
23. **`campisiBondAnal`（Campisi债券绩效归因）**：基于 Campisi 框架分解债券收益为收入效应（票息收入）、国债效应（收益率曲线变动）及利差效应（信用利差+个券选择）。
24. **`creditRiskRateDistribution`（信用风险评级分布）**：按主体评级与债项评级（AAA、AA+、AA、AA-及以下）统计债券持仓分布。

### 5. 衍生品与期货板块
25. **`overallFutures`（期货总持仓及收益）**：汇总股指、国债、商品期货的总名义本金、保证金占用、持仓保证金率与总盈亏。
26. **`commodityFutures`（商品期货板块收益贡献）**：黑色、有色、贵金属、能化、农产品板块的持仓权重与实现收益。
27. **`commodityFuturesExposureTiming`（商品期货净敞口时序）**：商品期货多头、空头及轧差后净敞口占基金净资产比例时序。
28. **`commodityProfitLoss`（期货十大盈利亏损品种）**：统计区间内持仓期货品种中正向收益前十与亏损前十的合约及金额。

### 6. 净值与业绩评价板块
29. **`netValue`（产品规模走势）**：双 Y 轴呈现总资产规模（701A）、单位净值（702A）与累计单位净值（905）。
30. **`netValMonitor`（净值走势监控）**：单位净值、累计净值与沪深300/中证500业绩比较基准对照走势。

### 7. 风险计量与回撤控制板块
31. **`maxDrawdownFQ`（最大回撤与修复时序）**：自前期净值高点的动态回撤深度曲线、回撤起点日、谷底日及修复天数。
32. **`rewardRisk`（风险与收益指标）**：年化收益率、年化波动率、夏普比率（Sharpe）、索提诺比率（Sortino）、卡玛比率（Calmar）及胜率。
33. **`riskValue`（风险指标分析）**：95%、99% 置信度下的在险价值（VaR - Value at Risk）与预期损失（ES - Expected Shortfall）。

### 8. 交易行为与基础档案板块
34. **`tradeBehavior`（交易行为分析）**：组合月度/区间换手率（Turnover Rate）与交易频率。
35. **`tradeDuring`（区间交易分析）**：股票、债券、期货等资产的累计买入总额、卖出总额、净买入额及交易手续费。
36. **`productInfo`（产品基本信息）**：产品全称、简称、代码、投资经理、成立日、投资策略、基准代码及托管机构。

## 二、指标合并边界的业务决策原则

指标能否合并展示在一张表格中，底层受到 **四大不变约束** 的制约：

```
                              【合并审查决策树】
                                     │
                    ┌────────────────┴────────────────┐
                    │ 1. 数据时间形态是否一致？       │
                    │    (同为截面 或 同为日频时序)   │
                    └────────────────┬────────────────┘
                                     │ 是 (否 ──> 绝不合并)
                    ┌────────────────┴────────────────┐
                    │ 2. 分析实体粒度是否一致？       │
                    │    (同为产品级 / 行业级 / 资产级)│
                    └────────────────┬────────────────┘
                                     │ 是 (否 ──> 绝不合并)
                    ┌────────────────┴────────────────┐
                    │ 3. 分类标准体系是否一致？       │
                    │    (不可混淆申万体系与华泰体系) │
                    └────────────────┬────────────────┘
                                     │ 是 (否 ──> 绝不合并)
                    ┌────────────────┴────────────────┐
                    │ 4. 指标排序方向是否互斥？       │
                    │    (不可将Top盈利与Top亏损纵向混排)
                    └────────────────┬────────────────┘
                                     │ 是 (否 ──> 需分列独立展示)
                                     ▼
                            【允许合并为同一张表格】
```

## 三、可以合并展示的典型业务场景（黄金组合）

### 场景 1：申万行业投研综合全景表
* **合并模块**：`swInduStockAlloca`（配置权重）+ `swInduStockVala`（估值水位）+ `swInduStockAnal`（Brinson归因）
* **行主键**：申万一级行业名称/代码（共31行）
* **业务价值**：基金经理与投研人员最核心的看板。横向一览无余：
  $$	ext{行业} 	o 	ext{持仓权重} 	o 	ext{超低配比例} 	o 	ext{行业PE/PB} 	o 	ext{行业历史分位数} 	o 	ext{配置收益贡献} 	o 	ext{选股收益贡献}$$

## 四、绝对不能合并展示的业务场景（逻辑硬伤诊断）

### 1. 截面快照 与 历史时序 绝不能同表
* **冲突案例**：`positionIndustry`（最新行业持仓分布） $	imes$ `netValMonitor`（三年历史日频净值走势）
* **底层原因**：前者行主键是“行业代码”，只有最新1个截面；后者行主键是“交易日期”，有上千行记录。主键完全无对应关系，强行拼接只会造成全表错位。

### 2. 不同实体分析粒度 绝不能同表并列
* **冲突案例**：
  * 大类资产归因（`assetContribute`） $	imes$ 细分行业归因（`swInduStockAnal`）
  * 产品总体换手率（`tradeBehavior`） $	imes$ 前十大重仓股票明细（`topTenOrTopFiveStockPositionTime`）
* **底层原因**：大类资产（股票/债券）是细分行业和个券的“父级集合”。若把股票大类与医药行业并列为同级行，表格下方自动求和时会发生**灾难性的重复统计（Double Counting）**，属于严重金融计算事故。

### 3. 不同行业分类标准 绝不能同表混排
* **冲突案例**：`swInduStockAlloca`（申万体系，31门类） $	imes$ `hsInduStockAlloca`（华泰柏瑞体系）
* **底层原因**：分类口径不可比。“申万医药生物”与“华泰柏瑞医疗保健”成份股覆盖和划分逻辑截然不同，无法按行横向对齐，更不能纵向拼在一起。

### 4. 不同资产类别的专属专业指标 绝不能同表
* **冲突案例**：`bondDurationTiming`（债券久期、凸性、基点价值 DV01） $	imes$ `commodityFuturesExposureTiming`（期货合约保证金占用、多空手数）
* **底层原因**：固收看利率敏感度，衍生品看杠杆乘数与基差。度量衡完全不互通，拼在一张表会造成大面积空值且失去业务可读性。

## 五、对既有 Wiki 文档中“合并描述”的缺陷诊断与修正

深入审查现有的 Wiki 文档（`resources/catalog/modules/*.md`）发现，原 Wiki 中关于合并的定义存在重大缺陷，必须在投研业务层面予以修正：

| 模块名称 | 原 Wiki 中的描述 | 存在的业务硬伤 | 科学的业务修正方案 |
| :--- | :--- | :--- | :--- |
| **`commodityProfitLoss`**<br/>(期货十大盈利亏损品种) | `- 全部子模块：combined-table`<br/>`- 合并区分字段：盈亏类型`<br/>`- 合并统一字段：期货品种` | **破坏排名语义**：盈利前十是正收益且按降序排列，亏损前十是负收益且按升序排列。强行纵向堆成单列，导致排序列完全错乱。 | **左右双表并列**：左侧展示“十大盈利合约（降序）”，右侧展示“十大亏损合约（升序）”；或者提供两个独立 Tab 标签切换。 |
| **`netValue`**<br/>(产品规模走势) | `- 全部子模块：unsupported`<br/>`- 合并区分字段：不适用`<br/>`- 合并统一字段：不适用` | **一刀切不近人情**：因为一个子模块是表格（`latestNetValue`），另一个是折线图（`netValueTrend`），就判定不支持合并。但在实际 UI 页面中，两者自始至终是在同一卡片上一体化呈现的。 | **复合面板展现**：上方保留最新净值表格概览，下方紧贴规模走势图。数据层面虽然属于不同响应区，但属于强关联协同组件。 |
| **其余 34 个模块** | 全文无任何合并说明（完全留白） | **缺失业务场景指导**：只管单模块孤立展示，无法支撑用户“把申万行业配置、估值和归因放在一起看”的高频诉求。 | **按本文第三章“黄金组合”开放跨模块横向宽表支持**。 |
